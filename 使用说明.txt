■ 一、这是什么
----------------------------------------------------------------
一个可以独立运行的压缩包处理软件。双击「压缩包工具箱.exe」即可使用，
不需要安装 Python、7-Zip 或任何运行库 —— 压缩引擎已经打包在 exe 内部。

  压缩引擎：官方 7-Zip 26.03（LGPL，随程序分发）
  界面语言：简体中文
  支持系统：Windows 7 / 10 / 11（64 位）


■ 二、五大功能
----------------------------------------------------------------
【1】打包压缩
    把文件、文件夹压缩成 7z / zip / tar / tar.gz / tar.bz2 / tar.xz。
    · 压缩级别 0（仅存储）～ 9（极限）
    · 可选「边压缩边分卷」，例如每卷 4GB，直接产出 pack.7z.001 / .002 …
    · 支持密码加密（7z 格式会同时加密文件名）
    · 支持固实压缩、多线程

【2】分卷切割
    把「已经存在的」任意压缩包（zip / rar / 7z / iso / 视频 / 备份文件…）
    按指定大小切成 N 个分卷，或按份数等分。
    · 纯字节切割，不重新压缩 → 速度等于磁盘拷贝速度
    · 命名 file.zip.001 / .002 / …，7-Zip、WinRAR、HJSplit 都能识别
    · 可同时生成 SHA-256 清单和「合并还原.bat」备用

【3】合并还原
    选择 .001 分卷，自动找出后续所有分卷并合并还原成原文件。
    · 自动与清单中的 SHA-256 比对，确认一个字节都不差
    · 可选合并完成后删除分卷

【4】解压解包
    解压 7z / zip / rar / iso / cab / tar / gz / bz2 / xz / arj / lzh … 
    · 可以直接选择 .001 分卷，引擎会自动读取 .002、.003 …
    · 支持密码、覆盖/跳过/改名三种冲突处理
    · 内置「测试完整性」，可在解压前确认压缩包是否损坏

【5】查看内容
    读取压缩包内的文件清单：路径、原始大小、压缩后大小、压缩率、时间。


■ 三、关于「最大 4GB」分卷
----------------------------------------------------------------
本软件 1 GB = 1024 MB = 1,073,741,824 字节（1024 进制）。
所以「最大 4GB」= 4 × 1,073,741,824 = 4,294,967,296 字节。

「分卷切割」页签里点一下「4GB」按钮即可；也可以在「打包压缩」页签
直接把分卷大小设为 4GB，一次性产出分卷压缩包。

示例：一个 10 GiB 的压缩包按 4GiB 一卷切割 →
      .001 = 4.00 GB、.002 = 4.00 GB、.003 = 2.00 GB，共 3 卷。

■ 四、命令行模式（批处理 / 自动化）
----------------------------------------------------------------
  压缩包工具箱.exe --cli --help            查看全部命令

  :: 打包并分卷
  压缩包工具箱.exe --cli pack "D:\data" -o "D:\out\data.7z" -f 7z --volume 4GB

  :: 切割已有压缩包（最大 4GB）
  压缩包工具箱.exe --cli split "D:\backup.zip" --outdir "D:\out" --size 4GB --hash

  :: 合并还原
  压缩包工具箱.exe --cli merge "D:\out\backup.zip.001"

  :: 解压（直接吃 .001 多卷）
  压缩包工具箱.exe --cli extract "D:\out\data.7z.001" -o "D:\restore"

  :: 查看内容 / 测试完整性
  压缩包工具箱.exe --cli list  "D:\out\data.7z"
  压缩包工具箱.exe --cli test  "D:\out\data.7z"

  :: 加 --report result.json 可把结果写成 JSON，便于脚本读取


■ 五、把分卷传到网盘再下载合并，需要什么？
----------------------------------------------------------------
【必须有的】分卷本体，一个都不能少：
      backup.zip.001
      backup.zip.002
      backup.zip.003
      文件名必须原样保留。少了任意一卷、或中间缺号，都还原不出来。
      合并只需这些就够了，其它文件没有也能合。

【建议一起传的】两个几百字节的小文件，价值极高：
      backup.zip.splitinfo.json  （几百字节）
          记录原始文件名、原始大小、每卷字节数、SHA-256。
          有它，合并时能自动校验「下载回来的东西和原文件一个字节都不差」；
          没有它照样能合并，但只能核对大小，无法校验内容。
      backup.zip 的「合并还原_*.bat」  （几百字节）
          给没有本工具的接收方用：双击即可用 Windows 自带的 copy /b 合并。

【网盘的坑，按重要性排序】
1) 单文件大小上限（最容易踩）
   百度网盘非会员用 PC 客户端上传：单文件上限 4GB；
   用网页端上传：只有 1~2GB。会员 10GB，超级会员 20GB。
   ⚠ 我们的「4GB」= 4,294,967,296 字节，正好卡在临界值，容易被拒；
     而且它大于 40 亿字节，如果网盘按十进制口径卡 4GB 也会超。
   → 要传百度网盘，请在「分卷切割」里点「3.7GB 网盘」
     （3,972,929,536 字节），两种口径下都安全。
   → 且一定用 PC 客户端上传，别用网页端。

2) 文件名被改
   网盘客户端遇到同名文件会自动加后缀，变成
   「backup.zip.001 (1)」这种，合并就会失败。
   下载完先核对文件名是否为 xxx.001 / .002 / .003。

3) 别改扩展名
   不要为了「让它看起来像压缩包」把 .001 改成 .zip。
   改名后本工具就认不出分卷序列了。.001 直接选它就能合并/解压。

4) 传输静默损坏
   网盘上传下载偶尔会出错，而且不报错。所以下载完必须校验：
   用「合并还原」勾选校验 SHA-256（会自动和清单 .splitinfo.json 比对），
   或手工核对 —— 用下面命令算出还原文件的 SHA-256，
   看它是否等于清单里记录的值（以及是否等于你上传前的原文件）：
       certutil -hashfile backup.zip SHA256

5) 在线解压无效
   网盘的「在线解压」对字节切割出来的 .001 无效（它只是整个 zip 的一半）。
   要在线解压，请改用「打包压缩」页签里的「边压缩边分卷」，
   产出的 7z/zip 原生分卷，很多工具可以直接打开第一卷。
   （注意：tar.gz / tar.bz2 / tar.xz 不支持原生分卷。）

6) 容量与顺序
   分卷总大小 = 原文件大小，网盘剩余空间要够。
   合并按 001→002→003 顺序进行，与下载先后无关，本工具会自动排序。

【没有本工具时怎么合并（给接收方）】
   Windows 命令提示符：
      copy /b backup.zip.001+backup.zip.002+backup.zip.003 backup.zip
   或双击 合并还原_*.bat
   或 7-Zip / WinRAR：右键点 .001 → 提取到当前文件夹（会自动读后续分卷）
      —— 本工具实测：7-Zip 可以直接从 .001 读出内容，不必先合并
   Linux / macOS：
      cat backup.zip.00* > backup.zip


■ 六、常见问题
----------------------------------------------------------------
Q: 合并回来之后，双击 zip 提示「Windows 无法打开文件夹。压缩(zipped)文件夹无效。」
A: 文件没坏，是 Windows 自带解压不支持 ZIP64，属于系统限制。
   只要 zip 满足下面任意一条，就必须使用 ZIP64 扩展格式：
        · 总大小超过 4GB
        · 内部文件数超过 65,535 个
   而 Windows 资源管理器内置的解压（zipfldr.dll）只实现了 ZIP 2.0 规范，
   遇到 ZIP64 包必然报“无效”。比如一个 11.7GB、含 21 万个条目的包，
   两条全占，所以双击一定打不开。
   ⚠ 这与分卷、合并无关：原始 backup.zip 直接双击，报错一模一样。
   正确的打开方式（任选其一）：
     ① 本工具「解压解包」页签 → 选 .001 或选合并出来的 .zip
     ② 7-Zip / WinRAR / Bandizip 右键 → 解压（本机已装 Bandizip）
     ③ PowerShell（.NET 支持 ZIP64）：
        Expand-Archive -Path "backup.zip" -DestinationPath "D:\out"
   本工具在合并这类 zip 后，也会自动弹出上面的提示。

Q: 为什么 .001 用 Windows 自带解压打不开？
A: .001 是分卷，需要先合并。三种方式任选：
   ① 用本软件「合并还原」 ② 双击生成的「合并还原_*.bat」
   ③ 用 7-Zip / WinRAR 直接打开 .001（会自动识别后续分卷）
   注意：如果 .001 本身就是 7z/zip 的分卷压缩包（不是字节切割），
   用「解压解包」直接选 .001 就能解压，不需要先合并。

Q: 杀毒软件报警？
A: 单文件 exe 由 PyInstaller 打包，个别引擎会误报。源码在 build\ 目录下
   （archive_toolkit.py），全部使用 Python 标准库，可自行审阅或重新编译：
       cd build && python build_exe.py

Q: 分卷总大小会比原文件大吗？
A: 不会，分卷是纯字节切割，总大小与原文件完全相同（可能多一个几百字节的
   清单 JSON 和 bat 脚本）。

Q: 能不能压缩 rar？
A: 受 RAR 授权限制，任何第三方工具都不能创建 rar，但本软件可以
   正常「读取和解压」rar，以及把内容转存成 7z / zip。
